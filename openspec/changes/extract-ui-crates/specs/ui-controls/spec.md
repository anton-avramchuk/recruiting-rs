## Purpose
Общие контролы интерфейса (пейджер, диалоги, поля формы, вкладки, панель инструментов, индикаторы) и их единое поведение во всех приложениях.

## ADDED Requirements

### Requirement: Пейджер
Контрол `Pager` SHALL показывать подпись диапазона («с–по из всего») или «Страница N из M», кнопки «Назад» и «Вперёд» и, по необходимости, выбор размера страницы. Состоянием (страница, размер) владеет хозяин контрола; пейджер сообщает о намерении колбэками. Кнопки блокируются на границах. Расчёт числа страниц и диапазона MUST находиться в `ui-core`.

#### Scenario: Границы
- **WHEN** открыта первая страница или последняя
- **THEN** «Назад» соответственно «Вперёд» недоступна

#### Scenario: Размер страницы
- **WHEN** пользователь выбирает другой размер страницы
- **THEN** хозяин получает новый размер и возвращает список на первую страницу

#### Scenario: Один пейджер на всех
- **WHEN** в приложении есть постраничный список
- **THEN** он использует `Pager`, а не собственные кнопки

### Requirement: Диалоги
Контролы `Dialog`, `ConfirmDialog` и `Drawer` SHALL быть единственным способом показывать модальные окна и боковые панели: роль и подписи для скринридеров, фокус внутри окна, закрытие по Esc и щелчку по подложке (если закрытие разрешено), блокировка кнопок на время операции, место для ошибки. Прежние самодельные окна (панель человека воронки, палитра команд, шпаргалка клавиш) MUST использовать эти контролы.

#### Scenario: Закрытие по Esc
- **WHEN** открыт диалог и пользователь нажимает Esc
- **THEN** диалог закрывается без действия

#### Scenario: Занятый диалог
- **WHEN** идёт операция, начатая из диалога
- **THEN** кнопки диалога заблокированы, закрытие по Esc и подложке не срабатывает

#### Scenario: Ошибка в диалоге
- **WHEN** операция завершается ошибкой
- **THEN** сообщение показано в диалоге, окно остаётся открытым

### Requirement: Поля формы
Контролы `Field`, `TextBox`, `Textarea`, `NumberBox`, `Dropdown`, `Checkbox` и `DatePicker` SHALL связывать подпись, значение и ошибку проверки (`label[for]`, `aria-describedby`, `aria-invalid`), показывать ошибку рядом с полем и сохранять введённое при ошибке сервера. `Dropdown` принимает список пар «значение — подпись» и отмечает текущее значение; прямое использование `<select>` с ручным списком опций в приложениях MUST NOT остаться.

#### Scenario: Ошибка поля
- **WHEN** проверка поля не пройдена
- **THEN** рядом с полем показано сообщение, поле помечено как неверное для скринридеров

#### Scenario: Выбор из списка
- **WHEN** в `Dropdown` передан список вариантов и текущее значение
- **THEN** отмечен вариант с этим значением, выбор другого сообщает хозяину новое значение

### Requirement: Вкладки и панель инструментов
Контролы `Tabs` и `Toolbar` SHALL заменить ручные вкладки раздела «Безопасность» и разрозненные блоки кнопок. `Tabs` отмечает текущую вкладку (`aria-current`) по адресу страницы; `Toolbar` раскладывает кнопки и поиск единообразно и переносит их на узких экранах.

#### Scenario: Текущая вкладка
- **WHEN** открыта страница вкладки
- **THEN** её заголовок отмечен текущим, остальные нет

#### Scenario: Узкий экран
- **WHEN** ширина экрана меньше 640 пикселей
- **THEN** элементы панели инструментов переносятся, горизонтальной прокрутки страницы нет

### Requirement: Индикаторы
Контролы `Notice`, `EmptyState`, `Chip`, `Badge`, `Avatar`, `Card` и `PageHeader` SHALL быть общими; цвет несёт смысл только в статусах и ошибках. Инициалы и подписи статусов формирует `ui-core`.

#### Scenario: Аватар без фото
- **WHEN** у человека нет изображения
- **THEN** показаны его инициалы из `ui-core`

#### Scenario: Ошибка и пусто
- **WHEN** список не загрузился либо пуст
- **THEN** показаны `Notice` с ошибкой либо `EmptyState` с подсказкой одним и тем же видом во всех экранах
