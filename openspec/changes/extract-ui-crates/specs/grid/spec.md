## ADDED Requirements

### Requirement: Списки сущностей на гриде
Списки кандидатов, заказчиков, откликов и тенантов SHALL работать на общем `Grid` с серверными страницей, сортировкой, фильтрами и поиском в формате запроса `GridQuery`. На стороне сервиса каждый список описывается схемой `platform-grid` с белым списком полей. Существующие параметры `page` и `page_size` продолжают работать, ответ сохраняет вид `{items, total, page, page_size}`. Состояние видов списков хранится в адресе страницы.

#### Scenario: Сортировка и фильтр кандидатов
- **WHEN** пользователь сортирует кандидатов по столбцу и вводит фильтр
- **THEN** сервер возвращает отсортированную и отфильтрованную страницу, подпись пейджера пересчитана

#### Scenario: Неизвестное поле
- **WHEN** запрос списка содержит поле, которого нет в схеме
- **THEN** возвращается 400, данные не отдаются

#### Scenario: Изоляция организаций
- **WHEN** организация запрашивает любой из списков
- **THEN** в нём только её записи, фильтры не позволяют увидеть чужие

#### Scenario: Прежние параметры
- **WHEN** клиент запрашивает список только с `page` и `page_size`
- **THEN** список возвращается в порядке по умолчанию без ошибки

#### Scenario: Ссылка на вид
- **WHEN** пользователь открывает адрес списка с `sort`, `q` и `f.<поле>`
- **THEN** показан тот же вид списка
