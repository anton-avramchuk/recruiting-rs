## ADDED Requirements

### Requirement: Списки сущностей на гриде
Списки кандидатов, заказчиков и тенантов (на первой волне), а затем откликов SHALL работать на общем `Grid` с серверными страницей, сортировкой, фильтрами и поиском в формате запроса `GridQuery`. На стороне сервиса каждый список описывается схемой `platform-grid` с белым списком полей. Существующие параметры `page` и `page_size` продолжают работать, ответ сохраняет вид `{items, total, page, page_size}`. Состояние видов списков хранится в адресе страницы.

#### Scenario: Сортировка и фильтр кандидатов
- **WHEN** пользователь сортирует кандидатов по столбцу и вводит фильтр
- **THEN** сервер возвращает отсортированную и отфильтрованную страницу, подпись пейджера пересчитана

#### Scenario: Неизвестное поле
- **WHEN** запрос списка содержит поле, которого нет в схеме
- **THEN** возвращается 400, данные не отдаются

#### Scenario: Изоляция организаций
- **WHEN** организация запрашивает любой из списков
- **THEN** в нём только её записи, фильтры не позволяют увидеть чужие

#### Scenario: Прежние параметры
- **WHEN** клиент запрашивает список только с `page` и `page_size`
- **THEN** список возвращается в порядке по умолчанию без ошибки

#### Scenario: Ссылка на вид
- **WHEN** пользователь открывает адрес списка с `sort`, `q` и `f.<поле>`
- **THEN** показан тот же вид списка

### Requirement: Оператор «входит в перечень»
Фильтр грида SHALL поддерживать оператор `in`: значение поля входит в перечень `value` (массив не длиннее 200 значений). Оператор допустим для текстовых, числовых полей и идентификаторов; значения проверяются по типу поля, передаются параметром запроса, а не частью SQL. Пустой перечень не подходит ни одной записи. Регистр текстовых значений игнорируется, если не задано иное.

#### Scenario: Перечень идентификаторов
- **WHEN** фильтр содержит `id in [id1, id2]`
- **THEN** возвращаются только эти записи организации, чужие записи недоступны даже по прямому совпадению

#### Scenario: Пустой перечень
- **WHEN** перечень пуст
- **THEN** страница пуста, общее число равно нулю

#### Scenario: Неверные значения
- **WHEN** перечень длиннее 200 значений, не массив или значения не подходят типу поля
- **THEN** возвращается 400 с указанием параметра `filter`

### Requirement: Заказчики и архив в списке
Список заказчиков на гриде (`GET /clients/grid`) SHALL по умолчанию показывать только активных заказчиков, отсортированных по названию. Условие `archived = "all"` добавляет архивных (они идут после активных), `archived = true` оставляет только архивных. Прежний `GET /clients` возвращает массив и не меняется.

#### Scenario: По умолчанию без архивных
- **WHEN** список запрашивается без условия по архиву
- **THEN** в нём только активные заказчики

#### Scenario: С архивными
- **WHEN** задано условие `archived = "all"`
- **THEN** в списке активные и архивные, архивные после активных

#### Scenario: Только архивные
- **WHEN** задано условие `archived = true`
- **THEN** в списке только архивные заказчики
