## ADDED Requirements

### Requirement: Маршрутизация в несколько бэкенд-сервисов
BFF SHALL направлять запросы фронтенда в разные бэкенд-сервисы по allowlist: каждое правило указывает, в какой сервис уходит маршрут. Один токен сессии подставляется для всех сервисов. Маршрут вне allowlist MUST давать 404 и не пересылаться. Недоступность одного сервиса MUST NOT ломать маршруты других сервисов и вход.

#### Scenario: Разные сервисы за одним BFF
- **WHEN** авторизованный пользователь запрашивает маршрут пользователей и маршрут кандидатов
- **THEN** первый запрос уходит в identity, второй — в сервис кандидатов, оба с токеном его сессии

#### Scenario: Сервис кандидатов недоступен
- **WHEN** сервис кандидатов не отвечает
- **THEN** маршруты кандидатов дают 502, а вход и маршруты пользователей работают

#### Scenario: Маршрут вне allowlist
- **WHEN** запрошен путь кандидатов, которого нет в allowlist (например, служебный)
- **THEN** возвращается 404, запрос в сервис не уходит
