## Context

`AppShell` (ui-kit) общий для web-crm и web-admin: бренд, организация, строка поиска, пользователь, выход. Палитра и шпаргалка живут в `PaletteCtx` (web-crm), кнопка поиска передаётся колбэком `on_search`. Экран вакансий держит форму создания в локальном сигнале `creating`.

## Goals / Non-Goals

**Goals:** три кнопки шапки как в прототипе, меню «Добавить», права viewer, ссылка на форму вакансии.
**Non-Goals:** счётчик на кнопке «Разбор», тема, перенос навигации в боковую колонку.

## Decisions

- **Слот в `AppShell`**: необязательный `actions: Option<ViewFn>` (рендерится между спейсером и пользователем). web-admin его не передаёт.
- **Компонент `ShellActions` в web-crm** (`palette/actions.rs`): получает `PaletteCtx` и `writable`; кнопки «Добавить» (с меню), «Разбор», «?». Меню — `RwSignal<bool>` локально; закрытие по клику вне — слушатель `click` на окне, по `Esc` — `keydown` с `prevent_default` (чтобы остальные слои не закрылись), как в оболочке.
- **Меню доступно с клавиатуры**: кнопка с `aria-haspopup="menu"` и `aria-expanded`, пункты — ссылки `<A>` в `role="menu"`.
- **`?new=1`**: экран вакансий читает `use_query_map()` один раз при создании и начальное значение `creating` = `new==1 && writable`. Чистая функция `wants_new_form(query_value, writable)` покрывается юнитом. Пункт меню — ссылка `/vacancies?new=1`; команда палитры «Создать вакансию» переключается на тот же адрес.
- **Сигнальная точка** статична (акцент), без запроса данных.
- **Стили**: `.topbtn`, `.topmenu` в ui-kit рядом со стилями строки поиска; на узких экранах подписи сворачиваются в иконки/скрываются, остаются «+» и «?».

## Risks / Trade-offs

- Шапка становится плотнее на узких экранах → скрываем подписи кнопок до ширины 640 px.
- Если форма вакансии уже развёрнута, повторный переход по `?new=1` не закрывает её (форма только раскрывается).
