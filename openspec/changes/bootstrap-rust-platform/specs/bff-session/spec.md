## ADDED Requirements

### Requirement: Раздельные BFF для клиентского и админского слоя
Система SHALL предоставлять два независимых BFF: клиентский (для пользователей тенантов) и админский (для платформенных администраторов). Каждый фронтенд MUST обращаться к бэкенду только через свой BFF. Клиентский BFF MUST NOT проксировать admin-маршруты, админский BFF MUST NOT проксировать тенантные пользовательские маршруты.

#### Scenario: Admin-маршрут через клиентский BFF
- **WHEN** запрос к управлению тенантами приходит в клиентский BFF
- **THEN** возвращается 404, запрос не передаётся в сервис admin

#### Scenario: Независимая работа
- **WHEN** админский BFF недоступен
- **THEN** клиентское приложение продолжает работать

### Requirement: Токены не покидают сервер
BFF SHALL хранить access- и refresh-токены на сервере и выдавать браузеру только идентификатор сессии в cookie `HttpOnly`, `Secure`, `SameSite=Lax`. Cookie клиентского и админского BFF MUST различаться по имени и не приниматься «чужим» BFF.

#### Scenario: Вход
- **WHEN** пользователь успешно входит через BFF
- **THEN** ответ содержит cookie сессии и не содержит JWT ни в теле, ни в заголовках

#### Scenario: Cookie другого слоя
- **WHEN** cookie клиентской сессии предъявлена админскому BFF
- **THEN** запрос считается неаутентифицированным

### Requirement: Прозрачное обновление токена
BFF SHALL при истёкшем access-токене обновлять его по refresh-токену без участия пользователя; если обновление невозможно (токен отозван, тенант приостановлен), сессия завершается и возвращается 401.

#### Scenario: Истёкший access-токен
- **WHEN** запрос приходит с действующей сессией, но истёкшим access-токеном
- **THEN** BFF обновляет токены и выполняет запрос

#### Scenario: Приостановленный тенант
- **WHEN** refresh отклонён из-за приостановки тенанта
- **THEN** сессия удаляется, клиент получает 401

### Requirement: Защита от CSRF
BFF MUST отклонять изменяющие запросы (не GET/HEAD/OPTIONS) без проверочного заголовка CSRF.

#### Scenario: Изменяющий запрос без заголовка
- **WHEN** POST приходит с валидной cookie, но без заголовка CSRF
- **THEN** возвращается 403

### Requirement: Определение тенанта в клиентском BFF
Клиентский BFF SHALL определять slug тенанта для входа из поддомена или явного поля формы входа; после входа тенант берётся только из токена.

#### Scenario: Вход со slug
- **WHEN** пользователь отправляет форму входа со slug тенанта
- **THEN** BFF передаёт в identity вход в контексте этого тенанта
