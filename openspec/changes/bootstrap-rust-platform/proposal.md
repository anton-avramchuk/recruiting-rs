## Why

Рекрутинговая CRM (аналог Huntflow, ключевое обещание — скорость рекрутера) существует как .NET + Angular прототип (`recruiting-crm`, фреймворк `cheetah`). Нужна новая реализация целиком на Rust, включая фронтенд, и сразу мультитенантная — в .NET-версии она однотенантная. Прежде чем переносить домен (Person/Vacancy/Application), нужен рабочий скелет платформы, на котором домен будет строиться.

## What Changes

- Cargo workspace с микросервисной раскладкой (по образцу .NET-версии): отдельные бинарники, общие crates.
- Сервис **identity** со своей БД: пользователи тенантов, вход, выпуск и проверка JWT, роли.
- Сервис **admin**: реестр тенантов (создание, приостановка, активация), отдельные платформенные администраторы, провижининг первого пользователя тенанта.
- Два BFF — по одному на каждый фронтенд: **bff-crm** (клиентский слой, пользователи тенантов) и **bff-admin** (админский слой, платформенные администраторы). Каждый: cookie-сессия ⇄ JWT, прокси только к разрешённым ему сервисам, OpenAPI. Сессии, cookie и набор маршрутов у них раздельные.
- Два фронтенда на Leptos (SSR + hydrate) с общим crate UI-компонентов: **web-crm** (оболочка, вход, каркас навигации) и **web-admin** (вход администратора, управление тенантами). Каждый общается только со своим BFF.
- Мультитенантность: общая БД на сервис, колонка `tenant_id` + PostgreSQL Row-Level Security; общий crate, который устанавливает контекст тенанта на соединении.
- Общая инфраструктура: конфигурация, логирование/трейсинг, health-эндпоинты, миграции при старте, docker-compose с PostgreSQL и Redis, CI-проверки (fmt, clippy, test).
- Вне объёма: доменные сущности (Person, Vacancy, Application, Interview, Notes, Customer), события между сервисами (Redis bus), поиск, импорт/парсинг резюме, биллинг.

## Capabilities

### New Capabilities
- `tenancy`: определение текущего тенанта запроса и гарантия изоляции данных тенантов на уровне БД.
- `identity-auth`: пользователи тенанта, вход/выход, токены, роли и права доступа.
- `tenant-admin`: платформенное управление жизненным циклом тенантов отдельными администраторами.
- `web-shell`: интерфейс на Rust — клиентское приложение (оболочка, вход, навигация) и отдельное admin-приложение.
- `bff-session`: серверная сессия и граница доступа фронтендов к бэкенду; отдельный BFF для клиентского и для админского слоя.
