## Why

Сейчас у организации ровно три фиксированные роли: «Владелец», «Рекрутёр», «Наблюдатель». Владелец не может завести, например, роль «Стажёр» (только чтение и запись без удаления) или «Аналитик» (только чтение) под названием и правами своей организации. Нужен полный CRUD собственных ролей.

> Зависимость: change строится поверх `add-user-management` (экран «Безопасность», инвариант владельца, отзыв сессий). Его нужно заархивировать до архивации этого change.

## What Changes

- **Собственные роли организации**: владелец создаёт, переименовывает, меняет набор прав и удаляет роли. Роль = название + набор прав из `Чтение данных`, `Запись данных`, `Удаление данных` (запись и удаление требуют чтения). Право управления пользователями и ролями остаётся только у встроенного «Владельца» (иначе роль могла бы выдать себе владельца).
- **Встроенные роли** («Владелец», «Рекрутёр», «Наблюдатель») остаются, не редактируются и не удаляются; в списке ролей показываются как «встроенные».
- **Назначение**: пользователю можно назначить либо встроенную роль, либо одну собственную. В выбор роли на экране «Безопасность» попадают обе группы.
- **Удаление роли** запрещено, пока она назначена пользователям (409 с числом пользователей); название уникально в организации и не совпадает с названиями встроенных ролей.
- **Права в токене**: токен получает набор прав собственной роли (`perms`), и проверки прав в сервисах работают по ним так же, как по встроенным ролям. Изменение прав роли и смена роли пользователя отзывают refresh-токены затронутых пользователей (уже выданный access-токен действует до истечения срока).
- **Интерфейс**: на экране «Безопасность» появляется блок «Роли» (список, создание, правка прав флажками, удаление); проверки «можно ли писать/удалять» в CRM берут права из сессии, а не сравнивают названия ролей.

## Capabilities

### New Capabilities
- `roles`: собственные роли организации — CRUD, права, назначение, экран.

### Modified Capabilities
- `identity-auth`: роли и права учитывают собственные роли организации; токен содержит права собственной роли.

## Impact

- `platform-auth`: `Claims.perms` (необязательное поле), `Claims::has` учитывает его.
- `identity`: таблица `roles` (RLS), колонка `users.role_id`, HTTP `GET/POST /roles`, `PATCH/DELETE /roles/{id}`, выпуск токена с `perms`, миграция.
- `bff-core`/`bff-crm`: `perms` в данных сессии для интерфейса, путь `/roles` в allowlist `bff-crm`.
- `comment`: «владелец удаляет любые комментарии» проверяется по праву удаления данных вместо названия роли.
- `apps/web-crm`: блок «Роли», выбор роли пользователя с собственными ролями, `can_write`/`can_delete` по правам сессии.
- Тесты: API identity, права в токене и в сервисах, e2e «Безопасность → Роли».
