## 1. Общий код и identity (сначала красные тесты)

- [ ] 1.1 `platform-auth`: `Claims.perms` (необязательное, совместимо со старыми токенами), строковая сериализация `Permission`, `Claims::has` учитывает `perms`; юнит-тесты
- [ ] 1.2 `identity`: миграция (`roles` с RLS, `users.role_id`), домен `CustomRole` (название, права, инварианты) и правило «встроенные роли или собственная»; юнит-тесты
- [ ] 1.3 `identity`: `GET/POST /roles`, `PATCH/DELETE /roles/{id}` (уникальность названия, 409 при удалении назначенной роли, число пользователей, изоляция организаций, 403 для не владельца); OpenAPI; интеграционные тесты
- [ ] 1.4 `identity`: `role_id` в `POST /users` и `PATCH /users/{id}` (взаимоисключение с `roles`, чужая роль, смена на встроенную и обратно), `role_id`/`role_name` в ответе; инвариант последнего владельца с учётом смены на собственную роль; тесты
- [ ] 1.5 `identity`: права собственной роли в токене при входе и refresh; отзыв refresh-токенов при смене прав роли (не при переименовании); тесты, в том числе «собственная роль не управляет пользователями»
- [ ] 1.6 Сервисы данных: тест, что токен с `perms` даёт ожидаемые права (чтение/запись/удаление) в одном из сервисов; `comment` проверяет право удаления вместо названия роли
- [ ] 1.7 BFF: `perms` в данных сессии, путь `/roles` в allowlist `bff-crm`; тест
