# Proposal

## Why

Строка грида сейчас ведёт на страницу записи ссылкой в первом столбце: это неочевидно, не даёт отдельного действия «удалить» и не подходит для остальных списков. Нужен единый для всех таблиц способ работы со строкой: открыть редактирование двойным щелчком, видеть действия в строке и не удалять записи без подтверждения.

## What Changes

- `Grid`: двойной щелчок по строке открывает страницу редактирования; вместо ссылки в первом столбце добавляется столбец действий по умолчанию с действием «Изменить», а при передаче обработчика удаления — и «Удалить».
- Удаление из строки грида выполняется только после подтверждения в диалоге; после удаления грид перечитывается.
- Общий компонент диалога подтверждения в `ui-kit` (модальное окно с названием записи, «Удалить» и «Отмена», закрытие по Esc).
- Удаление собственной роли на странице роли тоже идёт через диалог подтверждения.
- Список пользователей получает столбец действий с «Изменить»; «Удалить» у пользователей не добавляется (пользователей блокируют, а не удаляют).

### Modified Capabilities
- `grid`: действия строки (двойной щелчок, столбец действий, подтверждение удаления); список пользователей получает столбец действий.
- `roles`: удаление собственной роли требует подтверждения.

## Impact

- `crates/ui-kit`: `grid/view.rs` (столбец действий, двойной щелчок, `on_remove`), новый компонент диалога подтверждения, стили.
- `apps/web-crm`: `security/view.rs`, `security/roles.rs`.
- e2e `web_security`: переход к записи теперь через двойной щелчок или «Изменить»; проверка диалога подтверждения.
- API и миграции не меняются.
