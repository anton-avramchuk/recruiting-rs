## Why

Рекрутинг ведётся для заказчиков, но «Аналитика» этого не знает: нельзя понять, какой заказчик приносит больше откликов, у кого лучше конверсия в интервью и быстрее закрываются вакансии, и нельзя посмотреть воронку и источники по одному заказчику. Данные для этого уже есть: у вакансии есть заказчик.

## What Changes

- **Таблица «Заказчики» в аналитике**: по каждому заказчику (и строке «Без заказчика» для старых вакансий) за выбранный период — вакансий, активных откликов, откликов за период, доля дошедших до интервью, вышедших на работу и медиана срока найма. Порядок: по числу откликов, затем по названию.
- **Фильтр по заказчику**: параметр `client_id` в `GET /analytics` сужает воронку, сроки, источники, динамику по неделям, повторных кандидатов и нагрузку на вакансии до вакансий этого заказчика; таблица заказчиков остаётся полной, чтобы можно было переключаться. Неверный идентификатор — 400, неизвестный заказчик — пустые метрики.
- **Интерфейс**: выбор заказчика рядом с переключателем периода («Все заказчики» по умолчанию), таблица «Заказчики» с переходом на фильтр по клику на строку и ссылкой на карточку заказчика. Смена фильтра без перезагрузки страницы.
- Без новых сервисов и миграций: заказчики и вакансии уже есть в `recruitment` (проекция и `vacancies.client_id`).
