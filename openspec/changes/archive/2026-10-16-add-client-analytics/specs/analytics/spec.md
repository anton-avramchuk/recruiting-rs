## ADDED Requirements

### Requirement: Аналитика по заказчикам
Система SHALL отдавать для каждого заказчика организации, у которого есть вакансии, и для строки «Без заказчика» (вакансии без заказчика), если такие вакансии есть: число вакансий, число активных откликов, число откликов за период, число и долю (в процентах, округление до целого) откликов, дошедших до «Интервью HR» и дальше, число вышедших на работу и медиану срока найма в сутках (по откликам периода на «Выход»; нет данных — значение отсутствует). Список упорядочен по числу откликов за период по убыванию, затем по названию; «Без заказчика» идёт последним при равенстве. Заказчик в архиве включается с признаком архива. Список заказчиков не сужается фильтром по заказчику.

#### Scenario: Сравнение заказчиков
- **WHEN** у Acme за период 4 отклика, 2 дошли до интервью, один вышел через 20 суток, а у Globex 2 отклика без интервью
- **THEN** первым идёт Acme (4 отклика, конверсия 50%, вышел 1, медиана 20), затем Globex (2 отклика, конверсия 0%, медианы нет)

#### Scenario: Старые вакансии
- **WHEN** есть вакансия без заказчика с откликами
- **THEN** в списке есть строка «Без заказчика» без идентификатора заказчика

#### Scenario: Заказчик без откликов
- **WHEN** у заказчика есть вакансия, но откликов за период нет
- **THEN** заказчик в списке с нулями и числом вакансий, медианы нет

### Requirement: Фильтр аналитики по заказчику
Запрос аналитики SHALL принимать необязательный `client_id`. С ним воронка, сроки найма и первого касания, источники, динамика по неделям, число повторных кандидатов и нагрузка на вакансии считаются только по вакансиям этого заказчика; без него — по всей организации. Некорректный `client_id` MUST давать 400; заказчик без вакансий или чужой организации даёт пустые метрики, а не ошибку.

#### Scenario: Воронка одного заказчика
- **WHEN** запрошена аналитика с `client_id` заказчика Acme
- **THEN** воронка, источники и нагрузка учитывают только отклики и вакансии Acme

#### Scenario: Неверный идентификатор
- **WHEN** `client_id` не похож на идентификатор
- **THEN** возвращается 400

#### Scenario: Чужой заказчик
- **WHEN** пользователь организации B указывает `client_id` заказчика организации A
- **THEN** метрики пустые, данные организации A не видны

## MODIFIED Requirements

### Requirement: Экран «Аналитика»
Раздел «Аналитика» SHALL показывать выбранный период (переключатель 30, 90, 180, 365 дней), выбор заказчика («Все заказчики» по умолчанию), три показателя (срок найма, первое касание, повторные кандидаты), воронку полосами с числом и конверсией на каждом этапе (этап с наибольшей потерей помечен подписью и начертанием, цвет сигнала не используется), столбцы откликов по неделям, таблицу источников, таблицу заказчиков (клик по строке заказчика включает фильтр, в строке есть ссылка на карточку заказчика) и нагрузку на вакансии (срок открытия свыше 45 дней выделен цветом сигнала). При отсутствии значения показатель выводится прочерком. При смене периода или заказчика данные обновляются без перезагрузки страницы.

#### Scenario: Данные на экране
- **WHEN** пользователь открывает «Аналитика» при наличии откликов
- **THEN** видны воронка с числами, таблица источников, таблица заказчиков и нагрузка на вакансии

#### Scenario: Смена периода
- **WHEN** пользователь выбирает «30 дней»
- **THEN** страница показывает метрики за 30 дней без перезагрузки

#### Scenario: Нет откликов
- **WHEN** в организации нет откликов
- **THEN** показатели выведены прочерками, воронка нулевая, показано пояснение «Данных пока нет»

#### Scenario: Фильтр по заказчику
- **WHEN** пользователь выбирает заказчика в списке или кликает строку в таблице заказчиков
- **THEN** воронка, источники и нагрузка пересчитаны для этого заказчика без перезагрузки страницы, таблица заказчиков остаётся полной, выбор можно сбросить на «Все заказчики»

### Requirement: Доступ и изоляция аналитики
Аналитика SHALL быть доступна ролям `owner`, `recruiter` и `viewer`; период задаётся числом суток от 7 до 365, значение вне диапазона MUST давать 400, как и некорректный `client_id`. Метрики считаются только по данным организации пользователя.

#### Scenario: Viewer читает
- **WHEN** `viewer` запрашивает аналитику
- **THEN** он получает данные организации

#### Scenario: Неверный период
- **WHEN** запрошен период 1 сутки или 1000 суток
- **THEN** возвращается 400

#### Scenario: Чужие данные
- **WHEN** аналитику запрашивает пользователь организации B
- **THEN** в метриках нет откликов, источников и вакансий организации A
