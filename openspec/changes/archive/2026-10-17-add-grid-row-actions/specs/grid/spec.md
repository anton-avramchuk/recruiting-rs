## ADDED Requirements

### Requirement: Действия строки грида
Компонент `Grid` SHALL открывать страницу редактирования записи двойным щелчком по строке и по умолчанию добавлять справа столбец действий. В нём всегда есть действие «Изменить» (ссылка на страницу записи), а действие «Удалить» показывается, только если для грида задан обработчик удаления и он разрешает удалять эту запись. Одиночный щелчок по строке ничего не открывает. Действия доступны с клавиатуры и имеют подписи для скринридеров. Грид без ссылки на запись не получает ни двойного щелчка, ни действия «Изменить».

#### Scenario: Двойной щелчок
- **WHEN** пользователь дважды щёлкает по строке
- **THEN** открывается страница редактирования этой записи

#### Scenario: Одиночный щелчок
- **WHEN** пользователь один раз щёлкает по строке
- **THEN** переход не происходит

#### Scenario: Действие «Изменить»
- **WHEN** пользователь нажимает «Изменить» в строке
- **THEN** открывается страница редактирования этой записи

#### Scenario: Нет обработчика удаления
- **WHEN** для грида не задан обработчик удаления
- **THEN** в столбце действий только «Изменить»

### Requirement: Подтверждение удаления
Удаление записи из грида SHALL выполняться только после подтверждения в модальном диалоге с названием записи и кнопками «Удалить» и «Отмена». Отмена, клавиша Esc и щелчок вне диалога закрывают его без удаления. После успешного удаления грид перечитывает текущую страницу; ошибка удаления показывается в диалоге по-русски, запись остаётся.

#### Scenario: Подтверждение
- **WHEN** пользователь нажимает «Удалить» в строке, затем «Удалить» в диалоге
- **THEN** запись удалена, грид обновлён

#### Scenario: Отмена
- **WHEN** пользователь нажимает «Удалить» в строке, затем «Отмена» или Esc
- **THEN** диалог закрыт, запись не изменена

#### Scenario: Ошибка удаления
- **WHEN** сервер отклоняет удаление
- **THEN** в диалоге показано сообщение, запись остаётся в списке

## MODIFIED Requirements

### Requirement: Список пользователей на гриде
Экран «Безопасность» SHALL показывать пользователей организации в `Grid` со столбцами «Пользователь» (имя и email, поиск), «Роль» (фильтр выбором), «Статус» (фильтр выбором), «Создан» (сортировка) и столбцом действий с «Изменить». Двойной щелчок по строке открывает страницу пользователя. Удаления пользователей нет: их блокируют на странице пользователя.

#### Scenario: Фильтр по статусу
- **WHEN** владелец выбирает статус «Заблокирован»
- **THEN** в списке только заблокированные пользователи

#### Scenario: Поиск пользователя
- **WHEN** владелец вводит часть email или имени
- **THEN** в списке только подходящие пользователи

#### Scenario: Большой список
- **WHEN** в организации больше 20 пользователей
- **THEN** список разбит на страницы, подпись пейджера показывает общее число

#### Scenario: Открытие пользователя
- **WHEN** владелец дважды щёлкает по строке или нажимает «Изменить»
- **THEN** открывается страница пользователя, действия «Удалить» в строке нет
