# Design

## Context

`Grid` (`crates/ui-kit/src/grid/view.rs`) делает первую ячейку ссылкой (`row_href`), других действий строки нет. Удаление пока есть только у собственной роли: кнопка на странице роли без подтверждения. У пользователей удаления нет (блокировка), у списка ролей нет грида: он состоит из встроенных и собственных ролей одним ответом без серверной пагинации.

## Goals / Non-Goals

**Goals:**
- Единое поведение строки во всех гридах: двойной щелчок, столбец действий, подтверждение удаления.
- Общий компонент подтверждения для грида и страниц.

**Non-Goals:**
- Перевод списка ролей и остальных списков на грид.
- Удаление пользователей.
- Массовые действия и выбор строк.

## Decisions

- **Столбец действий добавляет сам `Grid`**, а не вызывающий код: он знает о `row_href`, а удаление подключается необязательным параметром `on_remove`. Так каждый будущий грид получает действия одинаково.
- **`on_remove`** — структура `RowRemove<T>` с функцией подписи записи (для диалога), функцией «можно ли удалять запись» и асинхронным обработчиком, возвращающим `Result<(), String>`; текст ошибки показывается в диалоге. Вариант с обратным вызовом без результата не позволяет показать ошибку в диалоге.
- **Ссылка в первом столбце убирается**: доступность обеспечивает действие «Изменить» (настоящая ссылка), двойной щелчок — дополнение для мыши. Двойной щелчок игнорируется, если событие пришло от кнопки, ссылки или поля внутри строки.
- **`ConfirmDialog`** в `ui-kit`: модальный блок (`role="alertdialog"`, `aria-modal`), фокус на «Отмена», закрытие по Esc и щелчку по подложке, кнопка подтверждения блокируется на время запроса. Живёт в `ui-kit/components.rs`, чтобы использоваться вне грида (страница роли).
- **Перечитывание после удаления** — через счётчик версии, входящий в ключ `Resource` грида, без изменения адреса.
- **Без e2e на «Удалить» в гриде**: гридов с удалением пока нет. Поведение диалога проверяется на странице роли (тот же компонент), логика `RowRemove` — юнит-тестами; первый грид с удалением получит e2e сразу.

## Risks / Trade-offs

- Двойной щелчок не работает на сенсорных экранах → остаётся кнопка «Изменить».
- Проверка удаления из грида откладывается до первого потребителя (см. выше).
- Модальный диалог без нативного `<dialog>` требует ручного управления фокусом; делаем минимум: фокус на «Отмена», возврат фокуса на кнопку «Удалить» при закрытии.
