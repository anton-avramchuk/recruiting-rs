## Why

Каждый список в CRM (кандидаты, заказчики, отклики, пользователи) сейчас написан отдельно: свои параметры запроса, свой разбор на сервере, свои фильтры и пейджер в интерфейсе. Список пользователей в «Безопасности» вообще отдаётся целиком без страниц и фильтров. Нужен один общий контрол «грид»: серверная пагинация, сортировка и фильтрация с единым форматом запроса, безопасной сборкой SQL на сервере и готовым компонентом таблицы в интерфейсе. За образец взят грид из `cheetahrc` (страница, сортировка по нескольким полям, рекурсивный фильтр `and/or`, белый список полей, один компонент `Grid` с поиском, фильтрами столбцов и пейджером).

> Зависимость: первое применение — список пользователей экрана «Безопасность» из `add-user-management`; тот change нужно заархивировать до архивации этого.

## What Changes

- **Контракт запроса и ответа** (`grid-contracts`, без зависимостей от сервера и браузера): страница и размер страницы, сортировка по нескольким полям, рекурсивный фильтр `and/or` с операторами `eq`, `neq`, `contains`, `startswith`, `endswith`, `gt`, `gte`, `lt`, `lte`, `isnull`, `isnotnull`, `isempty`, `isnotempty`; ответ `{items, total, page, page_size}`. Передача по HTTP: `GET ...?page=&page_size=&sort=поле:asc,поле:desc&filter=<JSON>`.
- **Сборка SQL на сервере** (`platform-grid`): схема грида — белый список полей (имя, SQL-выражение, тип, можно ли сортировать и фильтровать); поле вне схемы — 400; значения всегда параметрами с приведением типа; лимиты размера страницы, глубины и числа условий; стабильный порядок по ключу; общий `COUNT`. Работает в транзакции тенанта (RLS), поэтому изоляция организаций сохраняется.
- **Компонент `Grid`** (`ui-kit`): столбцы с сортировкой по заголовку, фильтры столбцов, общий поиск, пейджер («1–20 из 135», выбор размера страницы), состояния загрузки, пустоты и ошибки, строка-ссылка; состояние (страница, сортировка, фильтры, поиск) хранится в адресной строке, поэтому ссылку можно сохранить, а «назад» работает.
- **Первое применение**: `GET /users` в `identity` переходит на грид (ответ становится страницей `{items, total, ...}`; фильтры по статусу, роли, email и имени; сортировка), добавляется `GET /users/{id}` для страницы пользователя; список «Безопасности» строится на `Grid`.
- Виртуальная прокрутка и перевод остальных списков (кандидаты, заказчики, отклики) на грид в этот change **не входят**: они переводятся по одному отдельными изменениями с сохранением их нынешних фильтров. Вкладка «Роли» из `add-custom-roles` построится на этом же гриде.

## Capabilities

### New Capabilities
- `grid`: единый контракт запроса грида, сборка и безопасность запросов на сервере, компонент таблицы в интерфейсе.

### Modified Capabilities
- `identity-auth`: список пользователей организации с пагинацией, сортировкой и фильтрами; получение пользователя по идентификатору.

## Impact

- Новые crates: `grid-contracts`, `platform-grid`; `ui-kit` получает компонент `Grid` и зависит от `grid-contracts`.
- `identity`: схема грида пользователей, ответ `GET /users` меняется на страницу (ломающее изменение внутреннего API; потребитель один — `web-crm`), `GET /users/{id}`; тесты `users.rs` и `access.rs` обновляются.
- `apps/web-crm`: серверные функции пользователей принимают `GridQuery`, список «Безопасности» на `Grid`, страница пользователя читает по `GET /users/{id}`.
- `bff-crm`: путь `/users` уже пропускается; новых правил нет.
- Тесты: юнит-тесты сборки SQL (операторы, лимиты, инъекции), интеграционные тесты `identity` на Postgres, юнит-тесты состояния `Grid`, браузерный e2e «Безопасность» (страницы, сортировка, фильтр, поиск, адресная строка).
