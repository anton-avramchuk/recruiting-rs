## Context

Воронка (`add-hiring-funnel`) уже хранит отклики, считает время на этапе и просрочку, пишет историю и интервью. Не хватает рабочего экрана «что делать сейчас» и быстрого способа разобрать новые отклики. Прототип «Ритм» решает это страницей «Сегодня» и режимом разбора. Новых таблиц не нужно: сводка и интервью строятся из `applications`, `interviews`, `people`, `vacancies`.

## Goals / Non-Goals

**Goals:**
- Сводка одним запросом, без обхода всех откликов на клиенте.
- Одно правило просрочки: SQL-фильтр, признак в строке и счётчик в сводке не расходятся.
- Разбор клавишами без лишних запросов на карточку: данные следующей карточки подгружаются заранее.

**Non-Goals:**
- Серверное «отложено», напоминания, календарь, свободные слоты.
- Метрика «сэкономленное время» и сравнения с другими системами.
- Общая палитра команд и горячие клавиши (кроме T и клавиш разбора).

## Decisions

**Сводка: `GET /overview`.** Один SQL: `count(*) FILTER (...)` по `applications` с группировкой по этапу плюс подсчёт просроченных и новых старше суток и `count(*)` из `people`. Ответ: `by_stage` (все восемь этапов, нули включены), `new_total`, `new_waiting_over_day`, `in_work`, `overdue`, `people`. Перед чтением проекция людей синхронизируется, как у остальных чтений. Альтернатива «считать на клиенте по списку откликов» отклонена: потолок страницы 200 дал бы неверные числа на больших базах.

**Правило просрочки в SQL — в одном месте.** Условие просрочки живёт одной константой (`OVERDUE_SQL`) и используется и в сводке, и в фильтре `overdue=true`. Значения порогов берутся из `recruitment-contracts` (тот же источник, что у `Stage::overdue`), SQL собирается из них, а тест согласованности сверяет SQL-отбор с признаком в DTO на границах (24 часа, 5 суток, закрытые этапы). Альтернатива «вычислять признак после выборки в Rust» отклонена: ломает пагинацию и счётчик `total`.

**Интервью: `GET /interviews?from&to`.** Запрос по индексу `(tenant_id, scheduled_at)` с join на отклик, человека (проекция), вакансию. Период ограничен 31 сутками. Границы суток вычисляет браузер по своему часовому поясу и передаёт в RFC 3339: серверу часовой пояс пользователя неизвестен, и общий «сегодня» для организации не нужен. Интервью по откликам в отказе возвращаются со своим этапом (интерфейс показывает этап), а не скрываются.

**Очередь на разбор — существующий список.** Очередь = `GET /applications?stage=new&sort=match&dir=desc&page_size=200`. Порядок «совпадение по убыванию, без совпадения ниже» уже даёт сортировка `match` (`NULLS LAST`); при равных значениях добавляется вторичный ключ «дольше ждущие выше» (`stage_changed_at`), а не только `id`. Отдельного эндпоинта очереди нет.

**Режим разбора — маршрут `/triage`.** Отдельный полноэкранный маршрут вместо модального окна: состояние сеанса (очередь, индекс, таймер, счётчик) локально компоненту и исчезает при выходе, ссылка работает. Очередь снимается один раз при входе. «Отложить» только двигает индекс. Карточка человека собирается из `get_person` и `get_application` (последний даёт «другие отклики» и историю); данные следующей карточки запрашиваются заранее, пока рекрутер читает текущую. Действие выполняется серверной функцией; индекс увеличивается только после подтверждения (стадия `rejected` через `reject`, `screening` через `stage`), поэтому при ошибке карточка остаётся. Клавиши ←/→/↓ и Esc слушает обработчик окна, установленный в `Effect` (на сервере не выполняется); пока действие в полёте, повторные нажатия игнорируются.

**Клавиша T.** Общий обработчик в оболочке защищённой части: T вне полей ввода и вне открытой панели переходит на `/triage` для ролей `owner`/`recruiter`. Остальные клавиши придут с палитрой команд.

**Страница «Сегодня».** Берёт: сводку, очередь (первые девять из того же списка), интервью за сутки, список вакансий. Четыре независимых `Resource`, чтобы медленный запрос не блокировал остальные. Клик по строке очереди или интервью открывает уже существующую панель человека (`PersonPanel`) с общим `FunnelCtx`, а после любого изменения данные страницы перечитываются через версию. «Показать список» ведёт на `/applications?overdue=1`; таблица читает параметр из адреса и включает фильтр (добавляется переключатель «Только просроченные» в панель фильтров).

**Корень `/`.** Вместо перенаправления на «Вакансии» отдаёт «Сегодня»; «Сегодня» — первая в навигации.

**Оценка времени на разбор.** «Разобрать за N мин» — грубая оценка по числу откликов (6 секунд на отклик, минимум 1 минута); в интерфейсе подписана как оценка.

## Risks / Trade-offs

- [Сводка и список могут разойтись между двумя запросами] → страница перечитывает все блоки по версии после любого действия; расхождение допустимо между обновлениями.
- [Очередь снимается при входе, за время разбора появятся новые отклики] → они попадут в следующий сеанс; это поведение явно описано в спеке.
- [Отложенные снова появятся при следующем сеансе] → намеренно: серверного «отложено» нет, см. Non-Goals.
- [Часовой пояс пользователя определяет «сегодня»] → границы суток считает браузер; на сервере (SSR) до гидратации интервью не запрашиваются, чтобы не показать сутки по UTC.
- [Клавиши разбора конфликтуют с вводом текста] → обработчик игнорирует события из полей ввода.

## Migration Plan

Без миграций БД. Новые эндпоинты и фильтр аддитивны; откат — вернуть предыдущий образ `web-crm`: старая страница ожидает прежний набор маршрутов, которые не менялись.
