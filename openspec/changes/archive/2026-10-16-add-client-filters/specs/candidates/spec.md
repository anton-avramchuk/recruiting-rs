## MODIFIED Requirements

### Requirement: Список, поиск и фильтры
Система SHALL возвращать постраничный список кандидатов организации с общим количеством. Поиск `q` SHALL работать по ФИО, email, цифрам телефона и навыкам без учёта регистра; спецсимволы поиска обрабатываются буквально. Фильтры: источник, навык, диапазон стажа, диапазон ожидаемой зарплаты, список идентификаторов `ids` (через запятую, не больше 200; пустое значение не ограничивает выборку); фильтры комбинируются по «И». Сортировка по умолчанию — от новых к старым. Размер страницы по умолчанию 20, максимум 100; некорректные параметры страницы, некорректный идентификатор в `ids` и больше 200 идентификаторов дают 400.

#### Scenario: Поиск по части телефона
- **WHEN** запрошен поиск «123-45»
- **THEN** находятся кандидаты, в чьём телефоне есть цифры «12345»

#### Scenario: Комбинация фильтров
- **WHEN** запрошены навык «rust» и стаж от 3 лет
- **THEN** возвращаются только кандидаты, удовлетворяющие обоим условиям

#### Scenario: Постраничная выдача
- **WHEN** запрошена вторая страница из двух по три кандидата при пяти кандидатах
- **THEN** возвращаются два кандидата и total равен 5

#### Scenario: Спецсимволы
- **WHEN** поиск «100%»
- **THEN** «%» не работает как подстановка

#### Scenario: Только перечисленные
- **WHEN** запрошены кандидаты с `ids` из двух идентификаторов
- **THEN** возвращаются только эти двое (если они есть в организации), total равен 2

#### Scenario: Идентификаторы и другие фильтры
- **WHEN** заданы `ids` из трёх кандидатов и навык «rust», которым владеет один из них
- **THEN** возвращается только он

#### Scenario: Чужие и несуществующие идентификаторы
- **WHEN** в `ids` указаны идентификаторы кандидатов другой организации или несуществующие
- **THEN** они не попадают в выдачу, ошибки нет

#### Scenario: Некорректные идентификаторы
- **WHEN** в `ids` есть значение, не похожее на идентификатор, либо их больше 200
- **THEN** возвращается 400
