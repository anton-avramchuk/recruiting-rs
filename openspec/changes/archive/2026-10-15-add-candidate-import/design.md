## Context

Импорт из прототипа «Ритм» целиком живёт в браузере: разбор CSV/XLSX/PDF без библиотек, затем добавление людей в локальную базу. В нашей системе данные хранятся в сервисах, а выбранный вариант (разбор в браузере) требует, чтобы разбор работал и в wasm, и в тестах на образцах. Образцы пользователя особенные: XLSX с неверной контрольной суммой и «смешанными» строками (общие + встроенные), PDF с простым шрифтом, кодировкой WinAnsi и `Differences` для кириллицы.

## Goals / Non-Goals

**Goals:**
- Один чистый crate с разбором, проверяемый на образцах; без I/O и без зависимостей от Leptos.
- Слияние без дублей и частичный успех: плохие строки не мешают остальным.
- Минимальный объём wasm: никаких тяжёлых зависимостей (`regex`, `zip`, `pdf`).

**Non-Goals:**
- Серверная загрузка файлов, сканы, Identity-H без ToUnicode, `.xls/.docx`, несколько листов, нечёткое слияние, отмена импорта.

## Decisions

**Crate `candidate-import`.** Модули: `delimited` (CSV/TSV), `xlsx`, `pdf`, `resume`, `columns` (сопоставление), `rows` (преобразование строк и текста мест работы/образования в DTO импорта). Единственная зависимость — `miniz_oxide` (чистый Rust, без `unsafe`, собирается в wasm) для распаковки Deflate/Zlib. Альтернативы: `zip` (проверяет CRC и не читает образец), `calamine`/`pdf-extract` (тяжёлые, плохо в wasm), `regex` (≈1 МБ в wasm; нужные шаблоны — телефон, email, периоды, ожидания — проще написать вручную с тестами).

**XLSX без проверки CRC.** Читаем центральный каталог архива (конец файла → записи), берём нужные файлы по имени (`xl/sharedStrings.xml`, первый лист — по порядку `xl/worksheets/sheetN.xml`), метод 0 (stored) или 8 (deflate, `decompress_to_vec` raw). CRC и сжатый размер из заголовка игнорируются при несоответствии: размер берём из каталога, а при ошибке распаковки — сообщаем «не удалось разобрать файл». XML разбирается маленьким потоковым читателем (`<c r="B2" t="s"><v>3</v></c>`, `<is><t>…</t></is>`, сущности `&amp; &lt; &gt; &quot; &apos; &#N;`), номер колонки берётся из буквенной части ссылки ячейки. Лист идёт строками, пропуски заполняются пустыми значениями.

**PDF: простой извлекатель.** Алгоритм: найти объекты со `stream … endstream`; если в словаре `/FlateDecode` — распаковать (zlib), иначе взять как есть; в потоках содержимого разобрать токены, собирая строки операторов `Tj`, `TJ`, `'`, `"` и переводы строк по `Td/TD/T*/ET`; шрифт и его кодировка берутся из ресурсов страницы (первый найденный `/Encoding` с `/BaseEncoding /WinAnsiEncoding` и `/Differences [код /имя …]`). Байт → символ: таблица CP1252 для кодов вне `Differences`, а для кодов из `Differences` — имя глифа → Юникод (`afii10017`…`afii10097` для кириллицы, `uniXXXX`, имена латиницы). Поддержка `/ToUnicode` для простых шрифтов откладывается: если в шрифте нет читаемой кодировки, считаем долю читаемых символов (буквы/цифры/пробелы/знаки) — ниже порога 0,6 это «нечитаемо» и мастер предлагает вставить текст. Альтернатива «полноценный PDF-парсер» отклонена по размеру и сложности.

**Разбор резюме (`resume`).** Порт эвристик прототипа без регулярных выражений: email (токен с `@` и точкой в домене), телефон (последовательность из 10–11 цифр с `+7`/`8` и разделителями), ожидания (число из 4+ цифр перед `₽`/`руб`/`р.`), опыт («опыт … N лет», «N лет опыта»), город (словарь), навыки (словарь `TAGS` без учёта регистра и по границам слов), места работы (строка с периодом `YYYY — YYYY|наст. время`, остаток делится по запятой/тире на компанию, должность и примечание; при пустом остатке берётся следующая строка), образование (строка с «университет/институт/академия/колледж/вуз»), имя (первая из 14 первых строк из двух-трёх слов с заглавной без цифр и служебных слов), выжимка (первая длинная строка, не попавшая в другие поля). Словари городов и навыков — общие данные crate. Результат — структура с полями и признаками «найдено/не найдено».

**Преобразование в данные кандидата.** Периоды «2021 — наст. время» → место работы с началом `2021-01-01` и без окончания; «2020 — 2026» → `2020-01-01 … 2026-12-31`; строка образования «2019 — МФТИ — Прикладная математика» → `year_to = 2019`, учреждение и специальность. Строки с неразобранным периодом сохраняются в краткое описание/заметку, а не теряются. Ожидания и опыт приводятся к числам (`280 000 ₽` → 280000, «5 лет» → 5). Результатом является `ImportRow` — тот же набор полей, что принимает API.

**API импорта кандидатов.** `POST /persons/import` с телом `{rows: [ImportRow], default_source?}` (до 500 строк). Домен `candidate` получает функцию слияния `Person::merge_missing(&mut self, row)` (заполнение пустых полей, добавление недостающих навыков, мест работы и образования при их отсутствии) и использует существующие `Person::create` и `find_duplicate` (в тех же правилах приоритета). Пакет — одна транзакция `TenantTx`: строки обрабатываются по порядку, поиск совпадений идёт по базе и по уже созданным в этом пакете людям (после вставки следующая строка видит их), ошибка проверки строки не откатывает пакет. Ответ: `results: [{row, outcome: created|merged|rejected, id?, field?, message?}]` и сводка. Лента изменений `candidate` пополняется триггером как обычно, поэтому воронка узнаёт новых людей сама.

**API пакетных откликов.** `POST /applications/batch` с `{vacancy_id, person_ids, stage?, origin?}` (до 500). Перед обработкой проекция людей синхронизируется (импортированные люди появляются в ней по ленте), вставка откликов — `INSERT … ON CONFLICT (tenant_id, person_id, vacancy_id) DO NOTHING` одним запросом, события истории вставляются для действительно созданных откликов. Счётчики: `created`, `skipped`, `missing`.

**Мастер в `web-crm`.** Маршрут `/candidates/import`; состояние шага — сигналы страницы. Файл читается через браузерный `File.arrayBuffer()` (web-sys `File`, `Blob`, `DragEvent.dataTransfer.files`, `wasm-bindgen-futures`), расширение определяет разборщик. Для таблицы: превью (первые строки), таблица сопоставления (`<select>` на колонку), выбор вакансии/источника. Для PDF: форма полей, при нечитаемом тексте — текстовое поле для вставки. «Импортировать» режет строки на пакеты по 200, отправляет `POST /api/persons/import` и агрегирует результаты; если выбрана вакансия, собирает идентификаторы созданных и объединённых и вызывает `POST /api/applications/batch`. Итоговый экран показывает счётчики и список отклонённых строк с причинами; ссылки на список кандидатов и на отклики. Все обращения идут через `ui_kit::api::call` (браузер → BFF).

**Права.** Мастер доступен `owner` и `recruiter`; для `viewer` кнопка скрыта, а страница показывает сообщение (API всё равно отдаёт 403).

## Risks / Trade-offs

- [Эвристики резюме ошибаются на нестандартных текстах] → поля всегда редактируются перед импортом, ненайденное помечено; таблицы (основной сценарий) от эвристик не зависят.
- [PDF-извлекатель покрывает не все PDF] → нечитаемый результат распознаётся и ведёт к ручной вставке; ограничения описаны в спеке.
- [Транзакция пакета на 500 строк с дедупликацией по базе] → поиск по индексированным ключам, пакет ограничен 500 строками, клиент режет файл по 200.
- [Частичный успех усложняет повтор] → слияние идемпотентно: повторная загрузка того же файла даёт «объединён», а не дубли.
- [Размер wasm растёт] → без `regex`/`zip`, в wasm попадает только `miniz_oxide` и собственный код.
- [Часовой/регионный формат чисел и дат в Excel (даты как числа)] → даты в колонки не сопоставляются; числовые ожидания читаются как целые; неоднозначные значения отклоняются со строкой в отчёте.

## Migration Plan

Миграций БД нет: слияние и создание используют существующие таблицы, пакетные отклики — существующие. Эндпоинты аддитивны. Откат — вернуть предыдущие образы.
