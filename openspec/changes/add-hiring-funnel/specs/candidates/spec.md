## ADDED Requirements

### Requirement: Город и заметка кандидата
Система SHALL хранить для кандидата необязательные поля «город» и «заметка» (свободный текст рекрутера о человеке). Поля задаются при создании и правке по тем же правилам, что и остальные текстовые поля: пробелы по краям убираются, пустое значение означает «не указано». Заметка правится независимо от остальных полей. Город участвует в текстовом поиске по списку кандидатов.

#### Scenario: Город при создании
- **WHEN** кандидата создают с городом « Санкт-Петербург »
- **THEN** в карточке город «Санкт-Петербург»

#### Scenario: Очистка заметки
- **WHEN** при правке передана пустая заметка
- **THEN** заметка удалена, остальные поля не тронуты

#### Scenario: Поиск по городу
- **WHEN** в списке кандидатов выполняют поиск «казань»
- **THEN** находятся кандидаты с городом Казань

### Requirement: Лента изменений кандидатов для воронки
Сервис кандидатов SHALL публиковать для другого сервиса платформы (по сервисному токену, в разрезе организации) упорядоченную ленту изменений: для каждого кандидата — его последнее состояние (имя, источник, город, ожидаемая зарплата, email, телефон, навыки, стаж) или признак удаления. Лента позволяет читать только изменения после заданной позиции. Любое создание, правка контактов или профиля, смена мест работы (стаж) и удаление кандидата MUST попадать в ленту в той же транзакции, что и само изменение. Для кандидатов, существовавших до появления ленты, она заполняется при обновлении сервиса.

#### Scenario: Изменения после позиции
- **WHEN** потребитель запрашивает ленту с позицией, после которой изменили двух кандидатов
- **THEN** он получает последние состояния этих двух кандидатов и новую позицию

#### Scenario: Повторные правки
- **WHEN** один кандидат изменён пять раз с момента позиции потребителя
- **THEN** в ленте для него одна запись с последним состоянием

#### Scenario: Удаление
- **WHEN** кандидата удаляют
- **THEN** в ленте для него запись с признаком удаления

#### Scenario: Только своя организация и только для сервисов
- **WHEN** ленту запрашивают без сервисного токена или с токеном пользователя
- **THEN** возвращается 401, а лента одной организации никогда не содержит кандидатов другой

### Requirement: Удаление кандидата и воронка
При удалении кандидата сервис кандидатов SHALL сообщать об этом через ленту изменений, чтобы воронка удалила отклики этого человека. Интерфейс MUST предупреждать, что вместе с кандидатом удаляются его отклики.

#### Scenario: Предупреждение в интерфейсе
- **WHEN** владелец нажимает «Удалить» в карточке кандидата
- **THEN** подтверждение сообщает, что отклики кандидата будут удалены вместе с ним
