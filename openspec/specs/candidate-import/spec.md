# candidate-import Specification

## Purpose
Описывает импорт кандидатов из файлов: чтение таблиц (CSV, XLSX) и PDF-резюме в браузере, сопоставление колонок и пошаговый мастер, который заводит кандидатов (и при желании отклики на вакансию) без дублей.

## Requirements

### Requirement: Файл разбирается в браузере
Содержимое выбранного файла SHALL разбираться на устройстве пользователя; на сервер уходят только проверенные строки с полями кандидата, но не сам файл. Допустимы файлы до 5 МБ и до 2000 строк данных; превышение даёт понятное сообщение без попытки отправки.

#### Scenario: Файл не отправляется
- **WHEN** пользователь выбирает таблицу на 200 строк
- **THEN** сетевые запросы содержат только пакеты разобранных строк, а не содержимое файла

#### Scenario: Слишком большой файл
- **WHEN** выбран файл больше 5 МБ или с более чем 2000 строк данных
- **THEN** показано сообщение о лимите, импорт не начинается

### Requirement: Чтение CSV и TSV
Система SHALL читать текстовые таблицы: разделитель (`;`, `,` или табуляция) определяется по заголовку, поддерживаются поля в двойных кавычках с разделителями, переводами строк и удвоенными кавычками внутри, метка порядка байтов UTF-8 отбрасывается, пустые строки пропускаются. Файл без заголовка и хотя бы одной строки данных MUST давать сообщение «нет строк с данными».

#### Scenario: Таблица с точкой с запятой
- **WHEN** прочитан образец `demo-kandidaty.csv` (разделитель `;`, девять колонок, значения в кавычках)
- **THEN** получены заголовок из девяти колонок и две строки, значение `Go, K8s, PostgreSQL` осталось одним полем

#### Scenario: Кавычки и переносы
- **WHEN** в поле есть удвоенная кавычка и перевод строки внутри кавычек
- **THEN** поле читается целиком с одной кавычкой и переводом строки

#### Scenario: Пустой файл
- **WHEN** в файле только заголовок
- **THEN** сообщение «в файле нет строк с данными»

### Requirement: Чтение XLSX
Система SHALL читать первый лист книги XLSX: текст из общих строк и встроенных строк, числа, пустые ячейки с пропусками по номеру колонки в ссылке ячейки. Контрольные суммы архива не проверяются, поэтому файлы, собранные нестандартными инструментами, читаются. Сжатые и несжатые записи архива поддерживаются; не-XLSX файл с расширением `.xlsx` MUST давать понятную ошибку.

#### Scenario: Образец Excel
- **WHEN** прочитан образец `demo-kandidaty.xlsx` (общие и встроенные строки, неверный CRC)
- **THEN** получен заголовок «ФИО, Телефон, Почта, Город, Должность, Ожидания, Навыки» и строка «Ирина Соколова», а число 210000 прочитано как текст «210000»

#### Scenario: Пропущенные ячейки
- **WHEN** в строке заполнены только колонки A и D
- **THEN** строка содержит пустые значения в B и C, значения остаются в своих колонках

#### Scenario: Не архив
- **WHEN** выбран текстовый файл с расширением `.xlsx`
- **THEN** показана ошибка «не удалось разобрать файл», ничего не импортируется

### Requirement: Чтение PDF-резюме
Система SHALL извлекать текст из PDF с простыми шрифтами: потоки содержимого (в том числе сжатые Flate), текстовые операторы, строки в круглых скобках и шестнадцатеричные, кодировка WinAnsi с таблицей `Differences` и названиями глифов кириллицы (`afii10017` …). Если доля читаемых символов в извлечённом тексте мала (шрифт-подмножество с Identity-H без таблицы Unicode), система MUST предложить вставить текст резюме вручную, а не показывать нечитаемые поля.

#### Scenario: Образец резюме
- **WHEN** прочитан образец `demo-rezyume.pdf` (WinAnsi с Differences, несжатый поток)
- **THEN** извлечён читаемый русский текст с именем, телефоном, email и местами работы

#### Scenario: Нечитаемый шрифт
- **WHEN** текст из PDF состоит в основном из нечитаемых символов
- **THEN** показано предложение вставить текст резюме, ввод открывается пустым полем

### Requirement: Разбор текста резюме
Система SHALL разбирать текст резюме в поля: имя (первая строка из двух-трёх слов с заглавной буквы без цифр и служебных слов), телефон, email, город из известных списков, ожидания по числу рядом с рублём, опыт («N лет опыта»), навыки из известного списка, места работы по строкам с периодом лет («2019 — 2022» либо «2022 — наст. время»), образование по названию учебного заведения, краткую выжимку. Ненайденные поля остаются пустыми и помечаются «не найдено»; пользователь исправляет их до импорта.

#### Scenario: Разбор образца
- **WHEN** разобран текст образца `demo-rezyume.pdf`
- **THEN** найдены имя «Ирина Соколова», телефон `+7 916 442-11-07`, email `irina@mail.ru`, ожидания 210000, опыт 7 лет, навыки SQL, Python, dbt, PostgreSQL, три места работы и образование

#### Scenario: Текущее место
- **WHEN** в строке «2022 - наст. время, Ozon, Ведущий аналитик»
- **THEN** место работы начинается в 2022 году и не имеет даты окончания

#### Scenario: Ничего не найдено
- **WHEN** в тексте нет ни одного распознаваемого признака
- **THEN** все поля пусты и помечены «не найдено», импорт без имени невозможен

### Requirement: Сопоставление колонок
Для таблицы система SHALL предложить, какая колонка какому полю соответствует, по ключевым словам заголовка без учёта регистра («фио»/«имя»/name, «тел»/phone, «mail»/«почт», «город», «должн»/«позиц», «зарплат»/«оклад»/«ожид», «опыт»/«стаж», «навык»/«skill», «компан»/«места работы», «образован»/«вуз», «источник»/source, «коммент»/«замет»); если ничего не подошло, первая колонка считается именем. Пользователь меняет соответствие для каждой колонки или пропускает колонку. Импорт MUST быть недоступен, пока ни одна колонка не назначена имени.

#### Scenario: Автоматическое сопоставление
- **WHEN** загружен образец `demo-kandidaty.csv`
- **THEN** «Имя» → имя, «Телефон» → телефон, «Email» → почта, «Город» → город, «Должность» → должность, «Зарплата» → ожидания, «Навыки» → навыки, «Предыдущие компании» → опыт работы, «Образование» → образование

#### Scenario: Имя не назначено
- **WHEN** пользователь пропускает колонку с именем
- **THEN** показано предупреждение, кнопка импорта недоступна

### Requirement: Мастер импорта
Раздел «Кандидаты» SHALL содержать кнопку «Импорт» для ролей `owner` и `recruiter` (у `viewer` её нет), ведущую в мастер из трёх шагов: файл (выбор или перетаскивание), проверка разбора (для таблицы — сопоставление колонок с примерами значений, выбор вакансии и источника по умолчанию; для PDF — форма разобранных полей, вакансия, этап и источник), итог. Значения из строк преобразуются в данные кандидата: ожидания и опыт — числа, навыки — список, места работы и образование — записи с периодами (год начала и окончания). Строки отправляются пакетами и результат показывается итогом: создано, объединено с существующими, отклонено (с причинами по строкам), создано откликов.

#### Scenario: Импорт таблицы
- **WHEN** пользователь загружает образец CSV, выбирает вакансию и нажимает «Импортировать»
- **THEN** создаются двое кандидатов и по отклику на вакансию, итог показывает «создано 2, объединено 0, отклонено 0»

#### Scenario: Повторный импорт
- **WHEN** тот же файл загружается второй раз
- **THEN** новых кандидатов нет, итог показывает «создано 0, объединено 2», отклики не дублируются

#### Scenario: Отклонённые строки
- **WHEN** в одной строке нет имени, а в другой некорректный email
- **THEN** остальные строки импортируются, а итог перечисляет отклонённые строки с причиной

#### Scenario: Импорт резюме из PDF
- **WHEN** пользователь загружает образец PDF, исправляет город и подтверждает
- **THEN** создан один кандидат с контактами, навыками, тремя местами работы и образованием

#### Scenario: Роль viewer
- **WHEN** страницу «Кандидаты» открывает `viewer`
- **THEN** кнопки «Импорт» нет, прямой переход на `/candidates/import` сообщает о недостатке прав
